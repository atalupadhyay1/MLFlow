The one model everything hangs on

If you can explain these four ideas, you understand the course. Modules 3–12 are levers on them; module 13 pulls every lever.

1 · Brain vs brain with hands

Claude chat = a brain that advises. Claude Code = the same brain with hands — the hands are your terminal, which can create, edit, delete and execute.

2 · The agentic loop

Ask → plan → act → observe → check → retry or answer. Not magic — iteration at very high speed.

3 · Context is the scarce resource

LLMs are stateless: every message re-sends the whole history plus system prompt, tools, MCP, skills and CLAUDE.md. That drives cost, limits and “context rot”.

4 · Levers on that model

CLAUDE.md (memory) · skills (procedures) · hooks (zero-token automation) · MCP (connections) · subagents & teams (workers) · plugins (bundles) · scheduling (work without you).

The 10 rules to keep on your desk

  1. CLAUDE.md before code.
  2. One task, one session — /clear freely.
  3. /compact with explicit instructions when you must continue.
  4. Delegate bulk reading to subagents.
  5. Hooks for anything that must happen every time.
  6. Match the model to the job: plan strong, build balanced, maintain cheap.
  7. Only connect the MCP servers you actually use.
  8. Read any plugin or hook before installing — it runs with your permissions.
  9. Start automations read-only; gate the irreversible; log everything.
  10. Verify with commands, not vibes — put those commands in CLAUDE.md.

The 13 modules

Condensed revision notes. Full detail lives in 01-study-guide.md.

1 · Foundations 0:00

  • Anthropic builds Claude; OpenAI builds ChatGPT. Same category, different company — Anthropic positions as safety-first.
  • Tiers: Haiku (fast/cheap), Sonnet (balanced), Opus (most capable). Pick by job, not by ego: Opus to plan, Sonnet to build, Haiku to maintain.
  • Web/desktop Claude can advise and read screenshots but cannot touch your files. Claude Code installs on your machine and acts through the terminal.
  • Agentic loop: plan → act → observe → check → retry/answer.

2 · Install & auth 0:33

  • Native terminal install is the default path; macOS/Linux one-liner, Windows PowerShell or CMD — match your shell (Windows Terminal recommended).
  • Also available inside Claude Desktop (paid plan) and IDEs like VS Code.
  • “Trust this workspace” is the real security boundary: read, write and execute in that folder.
  • Subscription (Pro/Max, plan limits) vs API key (pay per token, required for programmatic/headless).
  • Sessions live under ~/.claude/ on disk — that’s how resume/rewind work.

3 · Commands, modes, .claude 1:22

  • Core commands: /model /effort /cost /context /compact /clear /rewind /branch /resume /agents /mcp /plugins /loop /init.
  • Switching models mid-session re-reads the full history — don’t thrash.
  • Permission modes: default (ask) → accept-edits → plan (read-only) → auto → don’t-ask → bypass (isolated only). Shift+Tab cycles.
  • .claude/ is hidden (ls -la): CLAUDE.md, settings.json, rules/, skills/, agents/, commands/, hooks/, MCP config. Project scope vs ~/.claude user scope.

4 · CLAUDE.md 2:58

  • The project’s permanent brain: stack, commands, conventions, guardrails, verification.
  • Priority, weakest → strongest: enterprise → user → project → CLAUDE.local.md. Closest to the project wins; Claude walks up the directory tree loading files as it goes.
  • Belongs: overview, essential commands, standards, structure, testing, hard rules, verification. Doesn’t: full API docs, drift-prone snippets, task-specific notes, secrets.
  • Bootstrap with /init; keep it small with imports (@docs/…).

5 · Context management 3:43

  • Every turn sends system prompt + tools + MCP + skills + CLAUDE.md + full history + auto-compact buffer.
  • Context rot: attention favours the start and end of a long context → ignored instructions, repeated work, new mistakes. It’s a management problem, not a model problem.
  • Tools: /context to inspect, /compact with instructions to continue, /clear for a fresh start, status file + new session for handover.
  • Cost model: history is re-billed every call — course example: ~200K context × 5 messages ≈ $3 ⚠️.

6 · Skills 4:31

  • Reusable playbooks: SKILL.md (name, description, trigger) + optional scripts/references/assets.
  • Progressive disclosure: only name + description sit in context until invoked — cheap at rest.
  • description drives auto-invocation; put deterministic steps in scripts; pin requirements.txt.
  • Locations: .claude/skills/ (project), ~/.claude/skills/ (personal), plugins. Build them fast with a skill-creator.

7 · Hooks 5:40

  • Scripts fired by lifecycle events — outside the model, zero tokens, deterministic.
  • Events: SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · Notification · subagent/task events · Stop · SessionEnd · pre-compact.
  • Contract: JSON on stdin; exit 0 = allow, exit 2 = block (stderr goes to Claude as the reason). Advanced: JSON permissionDecision.
  • Classics: notification, security guard on Bash, auto-format after Write/Edit, session logging.
  • Let Claude write your first hook (avoids settings clobbering), then test hooks by hand.

8 · MCP 6:49

  • Open standard for AI ↔ external tools/data. The toolbox you don’t have to build or maintain.
  • Connectors are ready-made; MCP is the extensible protocol. Local (stdio, your RAM) vs hosted (HTTP + API key).
  • Config in .mcp.json; secrets via ${ENV_VAR}; scopes: project (committed) / user / local (private).
  • Every server’s tool list costs context → enable only what you need. /mcp to inspect.
  • Build your own: expose functions with name + description + JSON-schema params. The description is the prompt for tool choice.

9 · Subagents 8:20

  • Isolated workers with their own context, prompt, tools and (optionally) cheaper model — only a summary returns.
  • Why: context hygiene, cost, focus, parallelism, safety via restricted tools.
  • Defined in .claude/agents/*.md / ~/.claude/agents/; invoke by natural language, @name, or /agents.
  • Rule of thumb: if it reads a lot to produce a little, make it a subagent.

10 · Agent teams 9:51

  • Team lead + teammates in separate sessions, messaging each other — not just reporting to a parent.
  • Isolation via git worktrees (own branch/checkout); lead merges. Shift+Down switches views.
  • Experimental flag: CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1 ⚠️. High token burn; supervise and review merges.

11 · Plugins & marketplace 10:35

  • Versioned bundles: agents + skills + commands + hooks + MCP + settings (+ CLAUDE.md).
  • Manifest .claude-plugin/<name>/plugin.json; hook commands use ${CLAUDE_PLUGIN_ROOT}.
  • /plugins → installed + marketplaces; add a marketplace by GitHub URL; enable via settings.
  • Community plugins are not reviewed — read before installing. Commit your plugin so the team gets it on pull.

12 · Scheduling 11:07

OptionWhereLaptop on?Triggers
/loopYour machine, current sessionYes (+ session open)Interval / cron, min 1 min ⚠️
Desktop taskYour machineYesTime
Claude routineAnthropic cloudNoSchedule / API / GitHub events
claude -pAnywhere you run itHost must runYour cron / CI
  • Cron executes blindly; scheduled Claude reasons about failure — reads errors, retries, documents, notifies.
  • Headless still respects permissions; it just never blocks on a prompt — which is what makes schedules trustworthy.
  • Safety: read-only first · non-destructive outputs · human gate for irreversible steps · log everything · test for days.

13 · Capstone: DailyPulse 11:56

FastAPI backend + React/Vite frontend built from a written spec: morning briefing, smart tasks (AI subtasks), standup generator, daily insights, weather, live AI news via Tavily.

  • Order: spec & CLAUDE.md → hooks → backend → test endpoints → frontend → fix CORS → live data → cron → recap.
  • Prompts written in advance, one per phase; optionally a second AI drafts them as “CTO”.
  • Lessons: compact before big asks (a bloated message cost ~$0.10 ⚠️); compress screenshots; app AI needs its own API key; degrade gracefully when the provider fails; the last 20% is where quality lives.

Hooks

{
  "hooks": {
    "PreToolUse": [{ "matcher": "Bash",
      "hooks": [{ "type": "command", "command": "python .claude/hooks/guard.py", "timeout": 10 }] }],
    "PostToolUse": [{ "matcher": "Write|Edit",
      "hooks": [{ "type": "command", "command": "python .claude/hooks/format.py", "timeout": 30 },
                { "type": "command", "command": "python .claude/hooks/log.py", "async": true }] }]
  }
}
  • exit 0 allow · exit 2 block (stderr → Claude) · other = non-blocking error
  • Or print {"hookSpecificOutput":{"permissionDecision":"deny","permissionDecisionReason":"…"}}

MCP config

{ "mcpServers": {
    "my-server": { "type": "http", "url": "https://…/mcp/",
                   "headers": { "X-API-Key": "${MY_API_KEY}" } } } }

Scopes: project (committed) → user → local (private). /mcp to inspect. Each server costs context every request.

CLAUDE.md template

# Project name
What it is, for whom, and the goal.

## Tech stack
- Backend: framework, port, storage, env vars
- Frontend: framework, port, data fetching, state rules

## Essential commands
- install / dev / test / lint / typecheck

## Code standards
- naming · typing · formatting · error handling

## Project structure
- path — responsibility (only what matters)

## Hard rules
- Never commit to main. Never hardcode credentials. No silent failures. Ask, don’t assume.

## Verification (after changes)
- code → typecheck + tests · UI → screenshot vs requirement · DB → test query
